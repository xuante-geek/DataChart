# V3.0_Feature1 - 优化部署架构，解耦“程序与数据”

## 背景

当前 DataChart 的前端程序与 CSV 数据文件统一打包并提交到 GitHub。由于数据更新频率远高于程序更新频率，导致每次数据变更都需要发布程序版本，增加了维护成本。

## 目标

将 DataChart 调整为“前端程序静态发布 + 远程数据独立托管”架构：

- 前端页面继续作为静态站点由 GitHub 托管。
- 内置图表数据从固定远程地址读取，不再依赖仓库内本地 CSV。

## 远程数据源

- COS 域名：`https://anexus-data-1399092305.cos.ap-guangzhou.myqcloud.com`
- 数据目录：`/data`
- 当前文件：
  - `ERP_Interval.csv`
  - `Market_Thermometer.csv`

## 实施内容

1. 前端内置数据加载逻辑改为默认读取 COS 远程地址。  
2. 移除本地内嵌数据脚本依赖（`inline-data.js`）。  
3. 删除本地工程中冗余 CSV 文件（`ERP_Interval.csv`、`Market_Thermometer.csv`）。  

## 验收标准

1. 页面打开后，内置图表可在无本地 CSV 文件的情况下正常显示。  
2. 数据更新仅需更新 COS 的 CSV 文件，不需要修改 DataChart 程序代码。  
3. 仓库中不再存放上述业务 CSV 数据文件。  

## 注意事项

跨域访问需在 COS 侧开启 CORS，允许 GitHub Pages 域名访问 CSV 资源。
